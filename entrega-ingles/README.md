# English Deliverables — Overview for the Team

> Quick summary so everyone in the group can get oriented before reading the full
> documents. This folder contains our English-class deliverable: teaching non-technical
> people how to build and monetize a startup with AI, using **UniGrades** (a web app for
> students to track grades and GPA) only as the illustrating example.
>
> **Central message:** AI gives you the power to build and monetize almost any idea, as
> long as you solve a real problem.

## Files in this folder
- **`video-scripts.md`** — Ready-to-record script for a 10-episode TikTok series.
- **`ebook.md`** — The full ebook (12 chapters) we plan to sell. This is the product the
  videos drive people toward ("comment a keyword, get the link").
- **`README.md`** — This overview.

---

## Part A — The 10 TikTok episodes (video-scripts.md)

Each episode is 60–90s and includes: Title, Hook (first 3 seconds), What to say, What to
show on screen, and a Call to action. Every episode ends with an ebook CTA using a
**different keyword** so we can track which video converts best.

| # | Episode | Core idea (one line) | Ebook keyword |
|---|---------|----------------------|---------------|
| 1 | Find a Problem Worth Solving | Don't chase ideas, chase real problems that annoy people. | BUILD |
| 2 | Validate Before You Build | Ask 5–10 real people first; one afternoon beats two wasted months. | VALIDATE |
| 3 | Define Your MVP | Keep only the 3–4 features that solve the core problem. | MVP |
| 4 | Design It Simple | Make it work ugly before you make it pretty. | DESIGN |
| 5 | Build It with AI | You're the director; the AI types. Give it rules and a plan. | AI |
| 6 | Where Your Data Lives | A database = an organized Excel online, with rules nobody can break. | DATA |
| 7 | Publish It for Free | From laptop to a real public link, for zero dollars (GitHub + Vercel). | LAUNCH |
| 8 | Brand & Online Presence | Clear name, simple logo, and build in public. | BRAND |
| 9 | Make It Official | Register the company + get a tax ID — only when money moves. | OFFICIAL |
| 10 | Launch & Get First Users | Your first 10 users teach you more than the next 10,000. | START |

**The arc:** problem → validation → MVP → simple design → build with AI → data → publish →
brand → make it official → launch & grow. The startup *process* is the thread; UniGrades is
the example.

## Part B — The ebook (ebook.md)

12 chapters across 3 parts. Each chapter has: a plain-language explanation with an analogy,
the real story of what happened, a **"Real problem" box** (an honest obstacle we actually
hit), and an end-of-chapter **checklist** so the reader applies it to their own idea.

**Part 1 — Before Writing a Single Line of Code**
1. Find a Problem Worth Solving — great products start with problems, not ideas.
2. Validate Before You Build — get proof the pain is real for others, cheaply.
3. Define Your MVP — the smallest version that still solves the problem (the "3-dish restaurant").

**Part 2 — Building with AI**
4. Set the Stage: Give the AI Rules and a Plan — AI works far better with blueprints than random requests; Plan mode vs Build mode.
5. The Skeleton: Make It Work Ugly Before Pretty — function first; separate the look from the logic.
6. Where Your Data Lives — databases explained with zero jargon; public key vs secret key.
7. The Rules Nobody Can Break — put the critical rules in the database (the "bouncer," not just the friendly host).
8. The Front Door: Accounts and Security — sign-up/login; and why *removing* Google login was the smart call.

**Part 3 — Launch and Grow**
9. Publish It for Free — GitHub (warehouse) + Vercel (storefront); check no secrets ship.
10. Brand and Online Presence — simple identity + build in public; capture clips as they happen.
11. Make It Official — Cámara de Comercio (company exists) + RUT/DIAN (tax ID); only when money moves.
12. Launch and Get Your First Users — first users come from you; feedback is free upgrades; the "magic moment."

**The recurring "Real problem" boxes** (the honest obstacles that make it credible):
- A security vulnerability in the framework → upgraded before continuing.
- A tool command removed in a new version → migrated the config.
- Confusing public vs secret keys → never expose the secret one.
- The database created under the wrong account → rebuilt it (easy because it was versioned).
- Removing Google login → less friction, better product.
- Over-modeling features → cut them; "procrastination in a smart costume."

## How we'll use this (the business loop)
Solve a real problem → build it with AI → share the story honestly (TikTok) → viewers become
users or ebook buyers → feedback improves the product → repeat. The content series is the
marketing engine; the ebook is the product.
